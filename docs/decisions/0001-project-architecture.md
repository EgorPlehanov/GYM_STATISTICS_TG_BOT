# 0001. Модульный монорепозиторий с независимыми приложениями

## Статус

Принято.

## Контекст

Проект должен поддерживать Telegram-бота, обычную web-версию и Telegram Mini App. Все интерфейсы должны иметь доступ к полному функционалу тренировочной статистики.

## Решение

Используем один репозиторий с несколькими приложениями внутри:

```text
app/api
app/bot
app/workers
web
```

Backend API на FastAPI становится центральной точкой доступа к функциональности.

Бот и web frontend работают как API-клиенты:

```text
bot -> API
web -> API
Telegram Mini App -> API
```

Внутри backend логика разделяется на:

```text
API routers -> domain services -> repositories -> database
```

## Последствия

- Бизнес-логика не дублируется между ботом и web.
- API-контракт становится общей границей для всех клиентов.
- Бота не придется переводить на API позже, потому что он сразу строится как API-клиент.
- Разработка сложнее, чем прямой импорт domain из бота, но архитектура лучше готова к росту проекта.
