# 0004. Фоновые задачи через worker

## Статус

Принято.

## Контекст

Рейтинг и статистика могут пересчитываться после изменений тренировок. В будущем могут появиться тяжелые задачи: экспорт, отчеты, уведомления, периодические пересчеты.

## Решение

Выносим фоновые задачи в отдельный worker-service.

На первом этапе worker отвечает за пересчет рейтинга пользователя после создания, обновления или удаления тренировки.

Конкретный механизм очереди будет выбран отдельно.

## Последствия

- API быстрее отвечает пользователю после операций с тренировками.
- Появляется отдельный сервис в Docker Compose.
- Нужно определить retry policy, хранение ошибок и поведение при недоступности worker.
